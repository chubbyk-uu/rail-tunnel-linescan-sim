# 阶段 C：壁面目标规划与原始采集

2026-10-02：已实现目标规划、公开测量覆盖检查和 3 m 短程验证。完整 20 m 光学采集、畸变/平场处理后的拼接、匹配和全局优化尚未完成。

## 1. 输入约束

暂不加 IMU。重建只能读取原始像素、`config/observable_config.json`、公开曝光/门控记录、扫描编码器、左右测量轮编码器，以及从标定影像估计出的标定文件。左右轮的标定直径参与里程平均；不再误用 200 mm 行走轮直径替代 80 mm 测量轮直径。

不得输入 `evaluation/`、Gazebo/TF 仿真位姿、实际轮径、安装真值、光线命中、光学场景和缺陷真值。它们只能用于独立评估，评估结果不能反馈给拼接、缩小目标或补齐缺口。车体高度、姿态和轮径误差在没有可测证据时仍是未知量；名义覆盖通过不等于实际姿态下的覆盖已经得到证明。

采集只保存原始数据，不做畸变或平场补偿。后续在拼接前另行运行 `ssb_tools.optical_calibration apply`，保留原始数据，检查逐行饱和、光照和校正有效掩码。

## 2. 壁面目标与车体行程

RViz 的 `Task mode` 有两种模式：

- `Vehicle travel`：维持原有语义；输入车体起点与行程，最短 1 m，不能据此宣称同长度壁面已经完整覆盖。
- `Wall coverage`：输入壁面目标起点与长度，最短 1 m，范围在 0–20 m；从标定视场和运动参数规划车体前后超扫。启动后另行显示实际规划的车体区间，车辆初始化在该区间起点。

设目标为 `[X0, X1]`，最长连续有效标定视场相对扫描轴为 `[L, R]`，螺距为 `p`，公开名义相机安装纵向偏置为 `h`，巡航速度为 `v`，保护量为 `g=0.01 m`。一秒加减速段各需最多 `v/2` 距离；任一角度相位在巡航端点内最多一个螺距出现一次。车体规划为：

```text
vehicle_start = X0 - p - L - h - v/2 - g
vehicle_end   = X1 + p - R - h + v/2 + g
```

有效视场必须大于 `p+2g`，并检查车体和视场仍在已建模缓冲区内。周向像素足迹不足以覆盖名义行间距时拒绝该基线规划。目标、240° 角区、0.2 mm 检查网格和保护量在采集前写入 `inspection`，结束后不能改目标或把网格调粗来通过验收。原有 `acceptance.valid_x_m` 仍只是曝光行的轴向位置验收区，不能代替二维壁面覆盖。

当前标定连续有效视场为约 `[-0.420096, +0.420096] m`：

| 壁面目标 | 车体起止 | 车体行程 | 运动剖面时长，不含 2 s 接触稳定 |
|---|---|---|---|
| 3–6 m | 2.710096–6.289904 m | 3.579809 m | 19.899044 s |
| 0–20 m | −0.289904–20.289904 m | 20.579809 m | 104.899044 s |

这些是名义规划值，不使用仿真实际轮径或实际姿态；里程误差场景必须另行报告覆盖变化。

## 3. 运行

先重建，再使用新的输出目录：

```bash
source /opt/ros/jazzy/setup.bash
export COLCON_DEFAULTS_FILE=$PWD/colcon_defaults.yaml
colcon build

# 目标为壁面 x=3–6 m；仅保存原始图像，结束后检查公开几何覆盖。
bash tools/run_wall_capture.sh sessions/wall_3m_NEW 3 3
```

该入口保留 `sessions/wall_3m_NEW_inputs/` 中的生成端私有配置、世界和 `task.json`；这些不是重建输入。检查结果在 `sessions/wall_3m_NEW/reconstruction/coverage/`。需要暂停/继续时使用 `tools/run_mission.sh`，在面板选 `Wall coverage`；任务管理器结束后仍只保存原始图像，覆盖检查单独运行：

```bash
source install/setup.bash
python3 -m ssb_tools.wall_coverage \
  --session sessions/wall_3m_NEW \
  --calibration local_data/stage_b/contact_demo/calibration.json \
  --output sessions/wall_3m_NEW/reconstruction/coverage_NEW
```

旧会话没有预设 `inspection`，诊断时需显式传入 `--target-x 3 6`；这不构成采集前冻结的正式目标验收。停止或失败会话不能通过完整目标覆盖检查。默认演示素材仍需按 STAGE_B 的资产包流程恢复。

## 4. 覆盖判据与资源

轴向位置由左右测量轮累计计数和各自标定直径平均得出；扫描角由门控起点与扫描编码器插值获得。畸变查找表与平场静态有效列决定可用轴向区间；坏列形成的洞不会直接桥接。

**像素足迹与行间距不同。** 行间距由编码器倍分频决定，像素足迹由镜头与像元决定。本基线假设方形像元、居中且径向对称的镜头，用标靶影像拟合的逆映射 `x(qd)=c0+c1·qd+c2·qd²+c3·qd³` 的奇函数部分推算垂直方向增益 `c1+c3·qd²`，取所有有效列的最小值。对应周向足迹约 0.207 mm，名义行间距约 0.202 mm；曝光运动不用于扩大该足迹。它是名义模型假设，并非独立二维标定或实测 MTF。每行独立投射固定足迹，不把相邻行中点当作缺行补偿；删除曝光行的回归测试仍应检出缺口。

检查采用目标网格的像素中心，计算每个中心被多少条有效行覆盖。默认 0.2 mm，3 m 网格为 `57596×15000`，20 m 网格为 `57596×100000`。报告完整缺失像素数、重叠像素数、覆盖次数直方图及缺口边界，不用缩略图的采样结果代替全网格检查。

不分配整个稠密图。沿周向分块，扫轴向区间端点，将覆盖次数写成 `counts.bin`：每条记录为小端 `int32(q_bin, x_begin, x_end, count)`，共 16 字节，`x_end` 不包含。零覆盖区间也保留。`preview.png` 只用于观察（红色无覆盖、绿色单次、蓝色重叠）；`report.json` 给出全分辨率统计；`provenance.json` 自动记录工具代码版本、输入及输出哈希。

本检查尚不判断逐行饱和、模糊、遮挡或优化后的投影有效性。没有 IMU，实际车体姿态造成的几何偏移必须在后续独立评估中报告，不能由当前通过结果推断为零。

## 5. 验证记录

3 m 壁面目标的 Gazebo/OptiX 短程采集产生 341332 行，在原定 `[3,6] m×240°`、0.2 mm 网格上名义缺口为零。车体行程约 3.58 m；采集过程中不生成光学校正结果。一次无 GUI 测量的动力学实时率约 1.000、成像进度实时率约 0.994；这不能替代完整 20 m 或 GUI 联合运行的性能验收。

把该短程的公开配置、元数据和标定文件单独复制到没有原图、`evaluation/`、私有配置或场景资产的目录，再运行检查，覆盖次数文件与原会话逐字节一致。周向分块 257 与 512 行得到相同结果。

20 m×240°、0.2 mm **合成公开编码器规模测试**：1945577 条曝光行、57.596 亿个目标像素，名义缺口为零；一次测量覆盖检查 0.77 s，连同生成表文件约 1.01 s，峰值 RSS 约 380 MiB，覆盖次数文件约 59 MiB。该测试不渲染图像，不代表 20 m 实际采集已完成。复现：

```bash
source install/setup.bash
python3 tools/test_wall_coverage_scale.py \
  --reference sessions/wall_3m_NEW \
  --calibration local_data/stage_b/contact_demo/calibration.json \
  --output /tmp/ssb_wall_scale_NEW
```

回归覆盖不同初始扫描相位和 1/3/20 m 目标、独立稠密网格对照、双测量轮尺度、缺行与坏列、目标冻结、元数据路径限制及公开配置溯源。`tools/test_mission.py` 额外运行壁面任务并调用覆盖检查、阶段 B 验收和独立重放；`tools/test_mission_panel.py` 检查英文任务模式切换与发送字段。真实 20 m 采集后仍须检查哈希、行完整性、独立重放、接触动力学、GUI 实时率及峰值资源。
