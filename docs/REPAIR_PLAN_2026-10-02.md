## 贯穿实施的约束

- 重建输入只包含原始图像、公开编码器与曝光记录、公开配置和从标定影像估计的参数；生成端真值与评估输入不能进入拼接。
- 保持当前画质基线、0.2 m/s 巡航和 GUI 成像实时率至少 0.6 的目标。修复后按组件报告资源和耗时，不用平均值掩盖停顿。
- 用户补充：WSL 下避免大量小文件 I/O 和高频元数据操作。工作资产、采集及临时数据优先放在 Linux 文件系统的 `/home` 或 `/tmp`；不把高频工作目录放在 `/mnt/c` 等 Windows 挂载目录。
- 原始图像和表数据按有界缓冲顺序批量读写，不逐行生成文件。新增长图、掩码和日志沿用分块或连续文件，避免每个小窗口各建文件。
- 资产遍历、依赖扫描和哈希检查按阶段执行，避免在 GUI 刷新、状态发布或每行处理时反复递归扫描。缓存必须在输入变化时失效，不能省略必要的身份与完整性检查。
- 保留逐块回读校验；将耐久提交按阶段或明确批次组织，不逐行、逐预览或逐状态更新执行 `fsync`。同步仅针对本任务文件和相应目录，不用全局 `sync`/`syncfs` 扩大影响范围。
- 写盘由有界队列和明确背压管理，不靠无限积压绕过阻塞。分别记录写入、回读、同步耗时与队列等待；除总耗时外报告长停顿及收尾耗时。
- 不因优化 I/O 删掉哈希链、尾块记录或失败判据。climbot C#11 已记录逐图同步导致 I/O 尖峰，以及批处理优化误删回读校验的问题，见 [原始教训](../../climbot_sim/docs/INCIDENTS.md#11-耐久批处理优化扩大了完整性盲区syncfs-计时又被采样周期错开)。
