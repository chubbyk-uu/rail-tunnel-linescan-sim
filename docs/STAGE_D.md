# 阶段 D：重建方法与操作

更新：2026-10-04。D1 采后校正与展开、D2 重叠匹配、D3 连续轨迹优化和原图重采样已实现。接缝验收与当前证据见 [EVALUATION](EVALUATION.md)，未完成工作见 [ROADMAP](ROADMAP.md)。历次模型比较、失败、性能试验和旧门限保留在 [开发归档](history/STAGE_D_DEVLOG_2026-10-03.md)，不与现行结论混用。

## 输入与几何

只读取完成信息中的公开计数/哈希、`config/observable_config.json`、曝光/门控和编码器表、原始 Mono8 块及图像估计的标定文件。不读取 `evaluation/`、仿真位姿、实际轮径、安装真值或场景/缺陷资产。路径检查同时限制目录和文件符号链接，表和实际用到的原图块均校验哈希。

初始扫描轴位置与角度复用公开双测量轮和扫描编码器插值。标靶估计的逆镜头映射给出每个原始列在标靶距离上的轴向坐标，按名义半径/标靶距离缩放至壁面。模型假设扫描轴居中、线方向沿隧道轴向；未知的真实姿态与安装误差不被当作已知量。

暗场和平场在原始列上进行，浮点 DN 不裁剪，原始饱和与坏列保持无效。D1 v2（2026-10-03）不再落盘原始列浮点缓存：采样时直接从会话的 uint8 原图块读取相关行，按 `float32 (raw − offset) × gain` 校正（饱和 255 或无效列为 NaN），与原缓存逐位相同；原图块首次访问时按 D1 记录的哈希校验。畸变校正以几何映射保存，与展开采样合并，不先生成拉直图再作第二次空间插值。相邻有效曝光行之间做角向插值，遇到缺行或不连续的触发格点不跨越；有限像素足迹外无效，未标定边缘不外推。

每圈条带可用 `load_bands()` / `BandSampler.sample()` 独立按世界坐标窗口读取，供 D2 比较重叠区域。D1 初始全图在有效条带中选择原始列更靠近传感器中心的一圈，不做跨圈融合，也不拟合车体运动。

## 运行流程

先按 [部署文档](DEPLOYMENT.md) 构建并加载已安装包。输入必须是完成的 `Wall coverage` 会话；`Vehicle travel` 未预先声明壁面目标，当前不能直接用于正式 D1，也不能事后篡改归档配置补目标。下例中的 SESSION 和标定文件须属于同一光学条件，所有输出目录必须是新的。

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 -m ssb_tools.initial_unroll --session SESSION \
  --calibration local_data/stage_b/contact_demo/calibration.json \
  --backend cuda --output sessions/d1_NEW > /tmp/ssb_d1.log 2>&1
python3 -m ssb_tools.match_bands --unroll sessions/d1_NEW \
  --spacing-m 0.2 --output sessions/d2_NEW > /tmp/ssb_d2.log 2>&1
python3 -m ssb_tools.optimize_bands \
  --unroll sessions/d1_NEW --matches sessions/d2_NEW \
  --observable SESSION/config/observable_config.json \
  --attitude-spacing-m 0.02 --observed-knots \
  --output sessions/d3_NEW > /tmp/ssb_d3.log 2>&1
```

D1 默认 CUDA；`--backend cpu` 是显式选择，CUDA 失败不静默回退。可用 `--target-x A B` 在原定目标内诊断子区间，报告保留原目标；子区间不能冒充完整任务验收。当前正式参数为匹配间距 0.2 m、姿态节点 0.02 m、只在有曝光支撑的区间设置细节点；不依赖工具旧的 0.4/0.05 m 默认值。

## D1 输出与资源

`--mosaic none|roi|full` 默认 `none`，`roi` 另需 `--mosaic-x A B`。初始全图只供查看，D2/D3 不读它，最终全图从原图重新采样。

| 文件 | 内容 |
|---|---|
| `projection.npy` | 原始曝光序号、触发格点、圈号、编码器估计的轴向位置及扫描角 |
| `native_source.json` | 本区域用到的原图块（文件、首行序号、行数、SHA-256）、宽度及来源会话；D2 据此读原图 |
| `mapping.npz`、`calibration.json` | 测量镜头映射、有效标定域、名义角向足迹、逐列暗场/平场参数及标定 |
| `bands.json` | 每圈对应的行范围、实际记录的曝光边界、目标网格和坐标约定 |
| `coverage_runs.bin` | 全分辨率覆盖的精确游程（`q_bin, x_begin, x_end, count`，int32），零为无效、大于一为重叠；dtype 记在报告中 |
| `preview.png` | 每隔 stride 个网格中心的精确全图值，不需要先生成全图 |
| `overlap.png` | 每个预览格内的最小覆盖数：格内任一像素无效即为红色，不会被稀疏取样漏掉 |
| `overlap_*.png`、`review.html` | 最多三对相邻圈的原尺度复核窗口，固定 0–255 显示，无锐化和自动对比度 |
| `mosaic_u16.npy`、`mosaic_count.npy` | 仅 `--mosaic roi/full`：DN×64 四舍五入的 uint16（65535 为无效，量化误差 ≤1/128 DN）及独立条带数（uint8，255 饱和） |
| `report.json`、`provenance.json` | 缺口/饱和统计、覆盖直方图、全图选项、资源与限制、代码和输入/输出哈希 |

每个输出像素的采样来源由网格、曝光投影表、镜头映射和原图块共同确定，不保存坐标图或来源条带图。`trace_pixel(output, q_index, x_index)` 按与展开相同的条带顺序、评分和 float32 比较重算来源条带，恢复原始块、曝光序号、列号和权重；有全图时同时核对存储值。最终优化后从原始列重采样。

默认输出约 25 MB / 3 m、137 MB / 20 m；3 m 单幅全分辨率图另需约 2.4 GiB。50 m 默认展开预计 0.35–0.4 GB，单幅全图约 43 GB，仅是预算，尚未完成 50 m 端到端验收。原始采集、重成像和多份成果另计。

计算按默认 32×8192 像素块进行，原图 LRU 最多 128 块并受文件句柄限额约束。对外返回像素拷贝，不暴露可能因 mmap 淘汰失效的视图。批量顺序读写，阶段边界做哈希；不保存全部原始列浮点缓存，不生成逐窗口小文件。

## D2 匹配与环缝处理

D2 需要六个公共 D1 文件及 `native_source.json` 所列原图。搬家后传 `--raw NEW_RAW`，各块仍校验哈希；只搬小型 D1 文件不足以重建。相邻圈每 0.2 m 周向弧长取窗口，高 512、宽最多 1024 像素，匹配边缘区默认各 0.25 m，最多 4096 窗口、每窗 200 角点。

粗匹配后进行金字塔 LK、正反向检查、局部 NCC 和有效足迹检查。最少 24 个可信对应点，每五个点留出一个。局部仿射只验证对应点一致性，不直接变形成果图；谱范数、留出误差和内点比例门限由 MatchSettings 记录。失败窗口不贡献约束，缺行、饱和或未标定区不补齐。

长暗槽只从公开图像识别，不读板缝坐标。粗匹配使用有效背景，角点与光流的完整金字塔足迹避开槽带：当前保护半径 102 像素。训练与留出使用同一选择规则，原图和独立评价点不被遮掉；`--keep-long-structures` 仅用于关闭该策略作对照。

### 横滚、俯仰与局部模型

车体姿态变化不是单一整圈平移。对于理想居中轴、无偏航和升沉、扫描轴相对底座高度 h，令原始列沿轴方向斜率为 u、扫描角为 θ、小横滚为 α、小俯仰为 β，身体转动同时带动立柱顶端移动。线阵射线与圆柱求交的一阶扰动为：

```text
δx ≈ β[h + R(1+u²)cosθ] + hαu sinθ
δq ≈ −α(R+h cosθ) + Rβu sinθ
```

这是采用 Rx 正横滚、Ry 正俯仰的说明模型；实际安装、偏航、升沉还会增加其他项，D2 不代入真实姿态参数。它说明错位会随扫描角和原始列变化；立柱高度也不能忽略。D2 分窗口保留二维对应点，用局部仿射模型检查平移、剪切、微小转动和相对尺度的一致性。仿射系数不能直接解释为真实横滚/俯仰，更不直接作为整圈自由形变应用到最终图像。扫描周期重复的共同变化、绝对姿态和尺度仍有不可观测部分。

## D3 连续轨迹优化

编码器估计进度为自变量，三次 B 样条表示轴向位置、扫描相位、横滚和俯仰。位置/相位节点约 0.6 m，现行姿态间距 0.02 m，曝光空隙用较粗延拓。精确旋转和圆柱求交包含立柱顶端运动、传感器两端及姿态耦合；不开放逐窗口自由仿射。默认不拟合横向平移/升沉。固定安装误差开发新增 `--slow-translation`，以 0.6 m 粗节点增加有界横向/升沉、公共区间中点横滚锚定及名义先验；不是从真值读取外参。建模、可观测性限制与验收状态见 [MOUNT_ERROR](MOUNT_ERROR.md)。仅名义圆柱的轮径反例由下节共享深度修复，当前结果见 [WHEEL_ERROR](WHEEL_ERROR.md)；固定安装、更长轮径任务和带噪声组合尚未验证。

训练点局部稳健去趋势后按轴向、周向分别估计 MAD，最低 0.05 px；NCC 不当作权重。每窗信息上限相当于 16 个独立点。IRLS 对点与窗口加稳健权重，结合名义先验、曲率先验和坐标锚定，用稀疏 Gauss–Newton 求解；先验不被算作图像可观测性。留出点不参与求解、噪声估计或终止条件。

输出 `trajectory.json`、`match_residuals.npz`、窗口报告和溯源。`status=complete` 仅表示计算完成，图像一致性门限不能代替独立网格接缝、累计漂移和覆盖验收。单次系数最多 2048；50 m 分段求解仍待实现。

2026-10-04 review 修复：公开重建报告 v3 分别提供 `status=complete`、`audit_status` 和 `quality_status`；后者只表示位姿图像一致性。`public_reconstruction --strict` 在图像一致性失败或不可测时退出非零，`evaluate_global_geometry --strict` 要求全部独立几何门限通过。完整协议脚本启用两者；旧公开报告 v1/v2 保留原来的审计状态解释。

任务管理器用墙钟检查运行和暂停状态的遥测心跳，`--status-timeout-s` 默认 10 s；正常暂停仍须持续收到状态，失联进入既有失败和安全排空流程，恢复心跳不能自动恢复运行。启动保留 60 s 等待，排空仍采用进度期限。RViz 过期状态禁用暂停/恢复，停止保持可用。实际暂停、Gazebo 失联和健康 20 m 长任务均已验证，见验收文档。

### 从公开双圈图像估计径向深度

CUDA 全图反采样现采用 global ABI v2：每个输出 tile 的共享深度在 CPU 上按公开深度场计算，再传入 GPU；每圈反解都固定使用同一输出位置的深度。旧 ABI 会被明确拒绝。像素值、覆盖计数和无效掩码与 CPU 参考路径交叉验证，256 MiB GPU 缓冲预算包含深度数组。CPU 复核在输出范围内选非零深度探针，包含裁剪边缘的双线性支撑，避免块最大值位于目标外而漏检。名义映射、漂移和边界支撑明确关闭共享深度，避免将优化结果混入基线。

`public_reconstruction --surface-relief` 保留原位姿求解在 `pose/`，在新 `fit/` 中附加 `surface_relief.npz`。不是再次拟合车体位姿，也不读板缝位置、实际槽深、场景网格或材质标签。先用公开图像检测长暗槽，只对槽和周围背景进行双向密集对应；排除循环误差超过 1 px 的深度观测，拒绝非单调表面坐标的整行深度，保留这些拒绝统计。无深度支撑处维持名义圆柱，原始像素、覆盖检查和独立接缝点均保留。

估计径向深度的一阶关系为 `d ≈ Δx × R / B`，其中 Δx 是去除邻近板面对应偏置后的局部轴向视差，B 是拟合轨迹给出的相邻圈基线，R 是名义半径。深度限 30 mm、单幅立体计算限 1 MP、共享深度数组限 64 MiB；8 倍角向稀疏采样只用于平滑表面深度，不降低最终原图采样分辨率。两圈使用同一个深度场，输出周向坐标仍为名义 R×θ。给定输出位置，直接以该处共享深度求原图方向，避免在陡槽壁上迭代射线求交导致不收敛；最终 DN 仍只从原始列插值一次，无融合、亮度变换或删点。

预筛选和局部裁切减少位姿逆映射与立体计算；数据按角向块处理，深度集中保存在一个压缩数组文件，不创建逐像素或逐窗口文件。报告分别记录新增耗时、内存、双向支撑比例和非单调行数。深度数组纳入加载哈希校验和生产审计。正式留出使用协议 v7，额外冻结深度设置与源文件；未观察区域、深度边界混合、遮挡和绝对深度不可观测仍须如实报告，不把图像一致性当作网格接缝验收。

重采样加载已验证的轨迹后，在公开曝光进度上预计算样条修正并缓存；缓存的是图像拟合结果，不是实际位姿。系数、曝光进度或节点发生变化就重新直接计算，不能沿用旧值。缓存只驻留内存，上限 256 MiB，超出则使用原直接计算路径；不降低图像采样或深度质量。已验证缓存前后的像素、有效掩码及选圈评分逐项一致。`image_consistency` 继续表示原位姿拟合的留出残差，不作为密集深度步骤的独立留出证据；后者以新场景和光学网格评价验证。

### 局部姿态加密（可选）

`public_reconstruction --spacing-m .1 --height 256 --max-q-shift-mm 10 --adaptive-attitude` 先按既有 0.02 m 姿态节点求解，再对训练对应点的窗口残差计算二维中位数。超过 0.5 px 的一致偏移只触发一次局部节点分裂；留出点、真实位姿和材质标签不参与选择。每个子区间必须有至少两个独立接受窗口，节点间距仍不得小于两倍观测进度间距。只加密横滚/俯仰，不增加逐窗自由形变、升沉或尺度真值。

总系数仍限 2048，按训练误差优先分配成对节点；未能分配的候选明确记入 `attitude_refinement.budget_deferred_progress_m`。该模式先用于轮径误差的 3 m 试验。256 行窗口与 0.1 m 间距保留约一半的角向间隙；轴向搜索仍为 40 mm，显式周向搜索先验为 10 mm，超出先验或无足够支撑时拒绝匹配，不静默缩小范围。评价沿 0.1 m 的固定交错格点取样，仍按实际训练矩形标记窗口内/窗口间，原图和填缝点不剔除；默认 0.2 m 匹配和不加密的流程保持原身份。0.1 m 匹配在长任务上可能触及 4096 窗口上限，不能据短任务结果宣称 20/50 m 已支持该模式。图像误差改善也不能替代 1 px 主接缝验收。只做姿态加密的历史版本在新种子 81 mm 留出通过，但已知 80/81 mm 密集取点有窗口间超限；增加共享深度后的结果见 [WHEEL_ERROR](WHEEL_ERROR.md)，加密仍不启用为默认。

打开 `http://localhost:8765/review.html`。WSL localhost 转发不可用时，用 `hostname -I` 的地址替换 localhost。页面左侧为未经螺旋、畸变和平场补偿的原始条带，右侧是采后处理结果；名义展开是中间状态和 D3 定量基线。位置只从公开图像选，最大误差窗口另行保留。不能把去螺旋本身的效果全部归功于优化，也不把实际斜向裂缝强行拉直。

```bash
python3 -m ssb_tools.global_mosaic \
  --unroll sessions/d1_NEW --trajectory sessions/d3_NEW \
  --output sessions/full_NEW > /tmp/ssb_full.log 2>&1
python3 tools/validate_global_mosaic.py \
  --unroll sessions/d1_NEW --trajectory sessions/d3_NEW \
```

## 并行与实测性能

D2、独立评价 CLI 默认 `min(8, 当前可用 CPU 数)`，优先 affinity，支持 `--workers N`；D3 分块线程采用同一默认预算。固定分块和合并顺序不因线程数改变；脚本 `SSB_OFFLINE_WORKERS=N` 设置 D2 与评价，不设置 D3 线程。测试入口默认 4 个工作进程，另行调度。

| 本机记录 | 耗时 / 范围 |
|---|---|
| 2026-10-03 高环缝 3 m，未估计深度 | D2 9.95 s、D3 11.22 s，含暂存及哈希整链 23.75 s |
| 同次独立评价 | 12.03 s；不包括生成新全图 |
| 2026-10-03 20 m 预算，未估计深度 | D1 82 s、D2 51 s、D3 55 s、评价 35 s，约 3.7 分钟，不含采集 |
| 2026-10-04 20 m 共享深度流程，4 CPU | D2 73.44 s、D3 含深度 136.03 s，公开流程 226.94 s；不含 D1、独立评价及采集 |
| 同一共享深度流程的缓存对照 | 缓存前 283.31 s；深度 137.22 → 82.12 s，匹配、轨迹、深度及逐点评价不变 |

## 首尾双圈的公开支撑证明
