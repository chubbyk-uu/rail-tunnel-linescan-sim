# 重建性能与测量边界

当前 20 m 综合新采的阶段性能来自 [里程碑](MILESTONE_20M.md)，不是跨机器承诺。旧两轮优化的同输入 A/B、嵌套剖析、数值差异和归档身份见 [历史快照](history/D3_PERFORMANCE_SNAPSHOT_2026-10-05.md)。

## CPU/GPU 分工与资源

- 稳定分组索引替代逐窗口扫描全表。两轮共用经过身份和内容哈希检查的训练/留出划分与初始噪声权重；每轮重新执行稳健权重更新，不让留出点参与训练。
- C++ 融合公开光线求交、解析导数、加权残差及 CSR 写入，减少 NumPy 临时数组。固定分块保持 8 个 CPU 几何线程；262,144 个公开训练匹配的独立内核探针中，8 →16 线程只再快约 7%，不据此放大默认线程预算。
- CUDA 常驻公开光线、样条基、索引和权重，每次只上传系数向量；样条修正、残差和解析雅可比都在 GPU。CPU 保留稀疏正规方程、有界求解、可观测性及留出诊断。double 几何、禁用融合乘加、无浮点原子累加，固定索引保持确定的写入顺序。
- 单次拟合通过作用域释放 CUDA 对象，异常路径也关闭；失败明确报错，不静默切换 CPU。协议绑定 CPU/CUDA 数值库与源码哈希，生产输入仍只有机器人可获得的公开数据。

CUDA 优化工作分配上限 4 GiB，历史 20 m 工作分配峰值 2.113 GiB、主机 RSS 7.566 GiB；与最新采集设备总显存峰值 7.21 GiB/采集进程树 RSS 4.24 GiB 不是同一测量。全图 tile 使用独立 256 MiB GPU 预算。

## 运行预算与基准

D2/评价默认 min(8, 可用 CPU)，生产 CLI 默认 CUDA，Python 库接口默认 CPU；显式 `--geometry-backend cpu` / `numpy` 可对照，失败不自动切换。正式协议必须冻结实际数值库和后端身份。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 tools/benchmark_d3.py \
  --public sessions/milestone20_holdout_seed20270119_20261005/public_run/public \
  --matches sessions/milestone20_holdout_seed20270119_20261005/matches \
  --output sessions/D3_PROFILE_NEW --adaptive-attitude --slow-translation \
  --relative-encoder-scale --geometry-backend cuda > /tmp/ssb_d3_profile.log 2>&1
```

使用已安装模块和实际存在的公开输入；输出须新目录。上述只重跑位姿，不重新采集、不包含完整成图，也不是新独立留出。报告按阶段汇总，不新增逐窗口小文件。

50 m 前先设计分段和跨段约束，再在同公开输入做速度/正确性对照；当前 20 m 结果不能按长度简单外推成 50 m 保证，见 [ROADMAP](ROADMAP.md)。
